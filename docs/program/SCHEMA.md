# Program JSON schema (`assets/programs/*.json`)

`assets/programs/min_max_phase2.json` is generated by `tool/program/extract_min_max.py` from your own
copy of the PDF, which is never committed. The app parses it with `Program.fromJson`
(`lib/features/program/domain/program.dart`).

## Top level

| Field | Type | Notes |
|---|---|---|
| `schema_version` | int | 1. Additive changes keep the version; renames or removals bump it. |
| `program` | object | Identity and structure, see below. |
| `method` | object | Everything from the prose pages: effort, blocks, warm-up, techniques, progression, rest, supersets. |
| `days` | array | One entry per training day, in program order. |

### `program`

| Field | Type | Example |
|---|---|---|
| `id` | string | `min_max_phase2_5x` |
| `name` | string | `Min-Max Phase 2: Peak Physique (5x/week)` |
| `author` | string | `Jeff Nippard` |
| `source` | string | Provenance note. |
| `weeks` | int | `12`. After the last week the program loops to week 1. |
| `split` | string[] | `["Upper","Lower","Push","Pull","Arms"]` |
| `week_layout` | string[7] | Monday → Sunday: `["Upper","Lower","Rest","Push","Pull","Arms","Rest"]` |

### `method`

| Field | Content |
|---|---|
| `effort` | `scale` (`RIR`) and `definition`. `rir0_default` says to attempt and fail the last rep. `rir0_safety_exception` names the exercises where RIR 0 means no rep left but no failed attempt. Also `warmup_sets_effort` and `first_set_to_failure`. |
| `blocks[]` | `{block, weeks[], intro_week? \| deload_week?, description}` |
| `warmup.general` | `{duration, items[{name, dose, optional}], tip}` |
| `warmup.exercise_specific.by_count` | Map from `"1"`–`"4"` (number of warm-up sets) to a list of steps `{pct, reps:{min,max}}`. `pct` is a percentage of the planned working weight. |
| `warmup.exercise_specific.rest_between_s` | `{min, max}` |
| `techniques.<id>` | `{name, when, description, …}` plus extra fields per technique: `drops`/`drop_pct` (drop sets), `rest_s`/`reps_per_cycle` (myo-reps), `hold_s` (static hold), `used_in_this_version` (false for lengthened partials). |
| `progression` | `{rule, fallback, tracking}` |
| `rest` | `{working_sets, warmup_sets_s, between_exercises_s, faq}` |
| `supersets`, `substitutions`, `exercise_order`, `looping`, `four_day_option` | Prose rules. |

Technique ids: `drop_sets_2x25`, `myo_reps`, `weighted_static_hold_30s`, `lengthened_partials`.

### `days[]`

`{id, name, slots[]}`. A **slot** is one row of the PDF table. An exercise can have several slots on
the same day, for example a heavy row and a 1×20 high-rep row.

| Slot field | Type | Notes |
|---|---|---|
| `slot_id` | string | `<day>_<nn>`, e.g. `upper_01`. Stable; routines refer to it. |
| `exercise` | string | Exercise name as printed, without its superset prefix. |
| `superset` | string\|null | `"S1"`, `"S2"`, … Exercises sharing a prefix are a superset. |
| `warmup_sets` | `{min,max}` | Printed `2-3` gives `{2,3}`; printed `0` gives `{0,0}`. |
| `working_sets` | int | |
| `rep_range` | `{min,max,per_side,text}` | Printed `20` gives `{20,20}`; printed `10 per leg` gives `{10,10,per_side:true}`. |
| `rest` | `{min_s,max_s,text}`\|null | `null` when printed `-` (the first exercise of a superset). |
| `substitutions` | string[] | Usually 2 options; the wrist curl and wrist extension slots have 1. |
| `notes` | string | The PDF's coaching cue. |
| `rir0_attempt_failure` | bool | `false` for Hack Squat and Smith Machine Bench Press. |
| `source_pages` | int[12] | PDF page of this slot for weeks 1 to 12. |
| `weeks` | `{"1": {rir:[…], technique}, …, "12": …}` | `rir` has one entry per working set (null when printed `-`). `technique` is a technique id or null and applies to the **last** working set only. |

## Routines (`assets/programs/my_routines.json`)

Each routine is `{day, name, exercises[]}`. Each exercise row has:

| Field | Notes |
|---|---|
| `name` | Your name for the exercise (shown in the app). |
| `exercise_id` | Library id (free-exercise-db, or `sp_*` from `assets/extra_exercises.json`). |
| `sets` | Your working-set count. |
| `program_slots` | Slots this row takes its prescription from, in order. Sets fill the first slot's working sets, then the next. |
| `relation` | `program` (the program's exercise, possibly under another name), `substitution` (one of the slot's listed options), `swap` (your swap; inherits the replaced exercise's prescription) or `extra` (not in the program). |
| `program_exercise` | The program exercise this row stands in for. |
| `inherit_from`, `needs_confirmation`, `assisted`, `bodyweight` | Annotations; see the extraction report. |

## How a session is built

`prescribeSets(program, slots, sets, week)` expands a routine row into per-set prescriptions: rep
range, target RIR for that week, rest, and a technique on the last set of a slot.

`warmupSets(program, count, workingWeight, increment)` builds the warm-up pyramid from today's
suggested working weight. Warm-up percentages are rounded to the equipment increment and are never
lighter than one increment.

The suggestion engine runs once per slot (so the 1×20 set gets its own weight). It only looks at
history done at that slot's rep range (`TrainingHistory.logsForRange`).
